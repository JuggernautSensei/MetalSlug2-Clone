# 정리 기준 (JugX 작성자 스타일, "공격적" 범위: 결과 불변)

사용자 피드백: 헤더는 컴팩트하게, 주석은 적게, 과한 구조/방어 코드 없이 단순하게, "AI스러운 코드" 제거. 동작은 바뀌면 안 된다.

## 1. 헤더 (.h)
- 선언은 한 줄. 매개변수가 정말 많을 때만 줄바꿈.
- 후행 주석/필드 옆 설명 주석 금지. 이름이 설명하게 한다.
- 정렬은 clang-format 에 맡긴다.

## 2. 주석
- 지운다: 이름/타입을 반복하는 주석, 코드를 한 줄씩 풀어쓴 주석, 배너, 변경 이력, 긴 문단.
- 남긴다: 한 줄짜리 "왜" (수치 단위, 순서 의존, 결정성 이유, 외부 제약).
- 코드가 주석 제거 후 **전후 동일**해야 한다 (`Scripts/CodeDiff.ps1`로 확인).

## 3. 방어 코드
- 외부 입력(파일, JSON, 명령줄, 에셋 유무)의 실패 처리는 유지한다. 에러 메시지/코드/로그 문구는 바꾸지 않는다.
- 호출 규약상 일어날 수 없는 상태(널 서비스, 이미 초기화된 객체 등)에 대한 `if (!p) return;` / 상태 플래그 / 경고 로그는 `JUG_ASSERT` 한 줄로 바꾼다. 도달 가능한지 불확실하면 건드리지 않는다.
- Release 에서 assert 가 사라져도 정상 입력에서는 결과가 같아야 한다 (assert 식에 부수효과 금지).

## 4. 자작 미니 프레임워크
- AsyncLoader/MainThreadQueue → ImageLoader (2단계 S1~S6).
- 내부 전용 `Result` 전파는 줄이되, 외부 경계(파일/JSON 파서)의 `Result` 는 유지.

## 5. 웹스러운 구조 제거 (게임 엔진 스타일로)
- 만들지 않는다 / 있으면 없앤다: Job/Notice/Queue/통지/콜백, 구현이 하나뿐인 인터페이스 + 테스트용 가짜(IAudioSink, IStageHost), Builder/Factory/Manager/Service/Provider, 값을 나르기만 하는 *Context/*Diagnostics/*Config 묶음 구조체.
- 대신: 구체 클래스, `GetSingleton()`, 평문 구조체와 함수, 직접 호출. 다형성은 실제 구현이 여러 개이고 런타임에 갈릴 때만(IGameState).
- 테스트가 가짜 구현을 쓰던 곳은 구체 클래스(헤드리스 모드/Null 동작)로 바꾼다. 테스트 의도는 유지.
- 공격적 범위: 단일 구현 래퍼/인터페이스 해체, 중복(JSON 필드 리더, 헬퍼) 통합, 내부 `Result` 전파 축소를 허용한다. 단 새 클래스/새 파일을 만들지 않고 기존 파일 안에서 평평하게 한다.
- 결과 불변: Verify(해시/캡처/튜닝/단위 테스트)가 전부 동일해야 하고, 테스트가 검사하는 에러 코드/메시지는 유지한다.

## 5-0-a. 기존 클래스도 과감히 통합/삭제
- 하는 일이 얇은 클래스(한 곳에서만 쓰이는 래퍼, 멤버 몇 개와 getter 뿐인 클래스, 이름만 다른 중복 구조체)는 사용처로 흡수하거나 평문 구조체/함수로 바꾼다.
- 미니멀에서 멀어졌다고 판단되면 구조를 단순화하는 방향으로 합친다. 단 결과(Verify)는 동일해야 한다.
- 데이터 정의용 평문 구조체(`*Def`, `*Cfg`)는 구조체 자체는 문제가 아니므로, 사용처가 없는 것/중복만 정리한다.

## 5-0. C++ 관용구로 쓴다
- 값 타입/평문 구조체(public 데이터), 참조 우선, RAII(`Scoped`), 소멸자 정리.
- 분기는 `enum class` + `switch`, 상수 표는 `constexpr`, 일반화는 템플릿/concept.
- 고정 크기는 `ARRAY`, 크기가 정해진 컨테이너에 동적 할당을 쓰지 않는다.
- 문자열 키 조회는 데이터 로드 경계에만 두고, 로드 후에는 enum/인덱스/핸들로 직접 접근한다.
- getter/setter 나열, 불필요한 래퍼 클래스, 포인터 묶음 전달(*Context)을 만들지 않는다.

## 5-1. 새 코드 이름 규칙
- JugX 관례 (PascalCase, `m_`, `_`, `k`, `eX`, private `Foo_`, .cpp 헬퍼는 익명 NS `Foo_`, 소유는 `Scoped`).

## 7. 죽은 코드/리소스/파일 삭제
- 프로젝트는 완성형이므로 쓰이지 않는 코드, 에셋, 파일, 문서는 지운다. `git rm` 으로 지워 이력에 남긴다.
- 코드: 게임 exe 에서 도달할 수 없는 함수/클래스/파일(링커 `/OPT:REF` 결과 + 참조 grep), 그것만 검증하던 테스트.
- 리소스: 코드/JSON/스테이지/정의 어디에서도 참조되지 않는 파일. 접두 패턴으로 만드는 이름(`Boss_Turret_`, `{side}` 등)은 `Docs/Wayfinder/Cleanup.md` 의 판정 기준을 따른다.
- 파일: `Trash/`, 옛 스크립트/문서/캡처. 빌드·검증이 쓰는 것(`Baseline*.txt`, `Scripts/Verify|Regress|TraceLoad|Build`, `Test/Replays`)은 남긴다.
- 디스크에서만 존재해 복구 불가능한 untracked 파일(예: `Trash/**/*.mp4`)은 지우지 말고 사용자에게 알린다.

## 6. 검증
- 주석/서식만 바꾸는 패스: `Scripts/CodeDiff.ps1` 전후 동일 + 빌드.
- 코드가 바뀌는 패스: `Scripts/Verify.ps1` PASS (+ 로드 관련은 `Scripts/TraceLoad.ps1`).
