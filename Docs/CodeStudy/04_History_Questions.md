## 이전 작업 기록에서 확인된 문제

[ROADMAP](<C:/Users/Ahnjiwoo/Desktop/Projects/windowAPIProject(24.02.05)/MyMetalSlug2/Docs/ROADMAP.md>)의 검증 기록에 따르면, 구조 변경 중 오래된 오브젝트가 남은 증분 빌드 때문에 실패한 뒤 전체 재빌드로 해소된 일이 있었다. 이를 게임 로직의 결함과 빌드 산출물 불일치를 구별한 사례로 읽는다. 현재 분석에서는 같은 실패를 재현하거나 빌드하지 않았다.

이전 Slug 삭제 검증에서는 병렬 실행 중 uidemo 캡처가 기준과 달랐고, 단독 Verify는 기존 기준선을 유지한 채 통과했다. `App::Update_`는 일반 프레임에서 벽시계 delta를 고정 스텝 누적기에 넘긴다. 렌더 프레임 번호로 찍는 캡처와 고정 Tick 번호의 기록은 같지 않다. 한 번의 재시도 성공을 모든 상황의 픽셀 동일성으로 확대하지 않는다.

Audio의 별도 Vorbis 구현 TU를 게임 프로젝트에서 빼면 miniaudio가 호출하는 stb_vorbis 외부 기호가 링크 단계에서 해결되지 않았다. 현재 [AudioSystem.cpp](<C:/Users/Ahnjiwoo/Desktop/Projects/windowAPIProject(24.02.05)/MyMetalSlug2/Source/Audio/AudioSystem.cpp:9>)는 Vorbis와 miniaudio 구현을 같은 TU에서 생성한다. 이 변경 후 사용자가 테스트 실행을 제외했으므로, 이 문서에서 새 빌드/실행 성공을 주장하지 않는다. 선언만 포함하는 헤더와 구현을 생성하는 TU의 차이를 설명할 수 있어야 한다.
